# LangChain y cadenas LCEL: apuntes

LCEL es el operador pipe de LangChain. Una cadena se escribe asi:
prompt | modelo | parser. Cada eslabon recibe la salida del anterior.

El protocolo Runnable es lo que se gana gratis al usar una cadena: invoke, ainvoke
(asincrono), batch y abatch para listas, y stream y astream para tokens en vivo.
En aplicaciones web conviene ainvoke por defecto.

El prompt se declara con ChatPromptTemplate y las variables van entre llaves. No se
deben usar f-strings de Python dentro de la cadena porque el template tiene que ser
modular y encargarse el mismo de resolver las variables.

La salida estructurada se logra con with_structured_output y un esquema Pydantic: el
modelo queda obligado a devolver un objeto que cumpla ese contrato. Por debajo usa
tool calling o modo JSON.

Hay tres validaciones distintas. La sintactica verifica que el JSON sea parseable. La
estructural verifica que esten todos los campos. La semantica verifica que los valores
tengan sentido de negocio y esa la tiene que poner el desarrollador con restricciones
del tipo min_length o validadores propios.

with_retry reintenta errores transitorios como un 429 o un corte de red, con backoff
exponencial y jitter. No sirve para errores permanentes: si el prompt esta mal armado,
reintentar no lo arregla.

El parametro finish_reason indica por que termino la generacion. Si el modelo corto la
respuesta por falta de tokens, el objeto puede llegar incompleto y hay que detectarlo
antes de transformarlo.
